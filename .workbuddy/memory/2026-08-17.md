## 修复 JobGiver_SatisfyMetabolic 预定冲突报错
- 现象：睡眠时刷 "Could not reserve Thing_MEE_GlucoseMash... for maxPawns 10 and stackCount 0"。
- 根因链：JobDriver_Ingest.TryMakePreToilReservations 用 `FoodUtility.GetMaxAmountToPickup(food,pawn,job.count)` 作为 Reserve 的 stackCount；该函数对 spawned 物品内部调用 `reservationManager.CanReserveStack(pawn,food,10)`，当补剂堆叠已被其他小人/任务预定完时返回 0 → Reserve(stackCount=0) → 报错。原版 JobGiver_GetFood 生成任务前会检查可预定性，所以不踩坑。
- 修复（`_indexProj/Source/Comps/JobGiver_SatisfyMetabolic.cs`）：
  1. `FindItem` 地图搜索 validator 增加 `t.Map.reservationManager.CanReserveStack(pawn, t, 10) > 0`（与 JobDriver_Ingest 预定参数 maxPawns=10 一致）；背包内物品不受影响（原版 GetMaxAmountToPickup 对未 spawned 物品跳过 CanReserveStack）。
  2. `TryGiveJob` 开头增加睡眠判断：`pawn.jobs?.curJob?.def == JobDefOf.LayDown` 时 return null（JobDefOf 无 Sleep 字段，睡眠/卧床 job def 是 LayDown），避免半夜被叫醒补剂。
- 已 dotnet build 0 错 0 警，同步暂存 + 部署目录（md5 一致），grep 确认 CanReserveStack 编入 DLL。
