## 饮品 mod 水瓶配料报错：ThingCount stack count = -2147483648

**现象**：用 DBH_WaterBottle 的配方无法使用，报 `Tried to set ThingCount stack count to -2147483648`；GM 造的水同样报错。

**根因链（已核实）**：
1. `MakeFruitJuice` / `MakeMilkTea` 用了 `ingredientValueGetterClass=IngredientValueGetter_Nutrition`；
2. 该模式每个配料需求数 = `CeilToInt(count ÷ 配料营养值)`（IngredientCount.CountRequiredOfFor）；
3. **DBH_WaterBottle 营养 = 0**（NeverForNutrition），VCE_RawSugar/VCE_Salt 营养也是 0 → count÷0 = +∞ → (int)∞ = int.MinValue → ThingCount 校验告警、配料清单计算崩坏。
4. 与水瓶来源无关（GM 造的也一样），因为问题出在配方计算而非物品实例。
5. 另两个配方（电解质/功能饮品）没写 getter → 默认 `IngredientValueGetter_Volume` 对非 stuff 物品返回 1 → 无事。

**修复**：两个配方删除 nutrition getter（改默认 Volume 按件计），数量按原设计等价换算：生食植物 0.2营养→**4 件**、牛奶 0.2营养→**4 件**（0.05/件）。教训：**营养 getter 的配方里不允许出现 0 营养配料**。

## 追加：账单永远"缺水"——defaultIngredientFilter 漏了水瓶

**症状**：有很多 DBH_WaterBottle，但果蔬汁账单一直提示没有 water。
**机制（已核实）**：`Bill.cs:156` 账单的 `ingredientFilter` 从 `recipe.defaultIngredientFilter` **复制**；该字段缺省时 RecipeDef.ResolveReferences 会自动从 fixedIngredientFilter 复制（所以另外 3 个配方没事）。MakeFruitJuice 显式写了 defaultIngredientFilter 但只含 PlantFoodRaw → 账单过滤器**不允许水瓶** → 永远找不到水。
**修复**：defaultIngredientFilter 补上 DBH_WaterBottle（与 fixed 对齐）。已部署。
**注意**：**存档里已建的账单过滤器是建单时复制的旧值，不会自愈**——需删掉重建账单，或在账单的配料过滤 UI 里手动勾上水瓶。
