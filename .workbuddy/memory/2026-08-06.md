## 饮品 mod 新功能：口渴优先喝水瓶（自动寻找水瓶）

**需求来源**：用户开发文档 `F:\ObsdianProj\...\RimDrink拓展\饮品自动寻找水瓶.md`（写于反编译前，类名是猜的）。

**反编译 BadHygiene.dll 核实的关键事实**（用 probeproj 通用化改造：scan 模式列类型 / 传全名反编译整个类）：
- 口渴 JobGiver 实际是 `JobGiver_DrinkWater`（MinLevel 0.3）+ 子类 `JobGiver_DrinkWaterUrgent`（MinLevel 0，**不 override TryGiveJob** → patch 基类方法两个都生效）。
- TryGiveJob 原生顺序：①背包水瓶（SeekForThirst）→ ②`ClosestSanitation.FindBestDrink`（卫生设施+地图水瓶混选，**prio 并列 9**，近者胜）→ ③地表水 TryFindWaterCell。→ 近处有水槽就不喝库存水瓶，这就是要改的点。
- `WaterExt` 字段：`water` 是 **float**、`SeekForThirst` bool；`WaterExt.Drinks` 静态 HashSet。
- DBH 可用性惯例：`!IsForbidden && !IsBurning && pawn.CanReserve(t, 2)`；口渴≤0 时 Sprint，否则 Jog。
- DBH 设置 `DubsBadHygieneMod.Settings.AllowModdedDrinks=false` 时只认 DBH_WaterBottle（patch 里已尊重）。

**实现**（饮品 mod 新文件 `Source/DrinkingwaterIsGood/ThirstBottlePatch.cs`，**已手动加进 csproj 显式编译列表**）：
- `[HarmonyPatch(typeof(JobGiver_DrinkWater), "TryGiveJob")]` Prefix：
  1. 门槛对齐 DBH（thirst ≤ MinLevel、非 ShouldBeFedBySomeone、人类）；
  2. 背包有瓶 → return true（DBH 原生分支处理）；
  3. 地图搜瓶：扫缓存的"WaterExt 且 SeekForThirst 且 water>0"def → `GenClosest.ClosestThing_Global_Reachable`（Validator 按 DBH 惯例）→ 找到就 `JobDefOf.Ingest` count=1 并 return false 截断；
  4. 没有瓶 → return true 走 DBH（水槽/地表水）。
- 最终优先级链：背包水瓶 → 地图水瓶 → 水槽 → 地表水（饮水机预留位在文档里，未实现）。
- 编译 0 错 0 警，grep 确认入 DLL，已部署包内 Assemblies + Steam。

## 报错排查：DBH_WaterBottle 无法解析（根因 = DBH 口渴被关闭）

**现象**：`Could not resolve cross-reference to Verse.ThingDef named DBH_WaterBottle (wanter=thingDefs)`。

**排查链**：ModsConfig 启用的是**完整版 DBH**（`dubwise.dubsbadhygiene`，工坊 836308268，本地参考副本在 `D:\RimMods\otherMod\DBH\836308268`），不是 About.xml 里写的 Lite；完整版 1.6 Defs 里 DBH_WaterBottle 明明存在。反编译完整版主类 `DubsBadHygieneMod` 发现它 patch 了 `DefFromNodeNew`：**`Settings.ThirstNeed=false` 时丢弃所有带 `DBHThirst` 属性的 Def**——水瓶定义正带 `DBHThirst="true"`（注释：patched out when thirst is disabled）。

**结论**：用户在 DBH 设置里关了口渴 → 水瓶 Def 被移除 → 饮品配方引用解析失败。解决 = DBH 设置里打开 Thirst Need 并重启。无需改代码。

**注意**：饮品 mod `Refs\BadHygiene.dll` 是 **Lite 版**（2570319432 的 422912 字节），游戏跑的是完整版（400384 字节）；当前补丁 API 两边一致暂无影响，用完整版独有接口前需换 Refs 重编译。

## 诊断：copyToRimWorld.bat "不能正常执行"

现象：跑完 bat 后 mod 没更新 / 像坏掉。根因**不是 bat 逻辑错误**，而是最后一步 `copy /Y RimHormones.dll` 失败——游戏(RimWorldWin64.exe)运行时会锁住目标 `Mods\Rim-Hormones\Assemblies\RimHormones.dll`，Windows 禁止覆盖；bat 原代码对 `copy` 失败**不检查 errorlevel**，直接跑到 Done!，造成"脚本跑了但 DLL 没更"的假象。
- 证据：源 DLL 92160字节/23:51（最新）vs Steam 目标 90112字节/20:47（旧）。XML/Config 的 xcopy 正常。
- 加固 bat（`_indexProj/copyToRimWorld.bat`）：①开头 `tasklist|find RimWorld` 检测游戏运行并提示需退出；②新增【包内】Assemblies 同步（不被锁，永远最新，作为手动替换可靠来源）；③Steam DLL 复制加 `if errorlevel 1` 明确警告"被占用，请退游戏重跑或手动拷包内 Assemblies"。0Harmony.dll 仍从 `_indexProj\0Harmony.dll` 复制（存在）。
- 注：本机两个 shell 都禁止直接调 `cmd.exe`（Bash/PowerShell 均拦），无法由我实跑 bat 验证；已逐行核对语法标准正确。
- 结论：用户实际只需**完全退出游戏**后重跑 bat（或手动把包内 `Assemblies\RimHormones.dll` 拷到 Steam 目标）即可生效。
