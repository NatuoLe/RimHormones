## 装水 Job "取不出水" 根因与重构（仿 FDE：委托 DBH 原版扣水 + MEE 换瓶）
- 根因：之前 MEE 自己读 `CompWaterStorage.WaterStorage` 字段算"能取几瓶"，但该字段在单设施上值不对（DBH 管网总水量在 `PlumbingNet`，`CompPipe.pipeNetRef` 上），导致 `bottles=0` 一瓶都产不出；"每瓶0.5单位"的单位假设也不可靠。
- DBH 实测 API（MetadataLoadContext 挖得）：`CompWaterStorage` 有 `public float WaterStorage`；`CompPipe.pipeNetRef` 指向 `PlumbingNet`（管网总量）；`JobDriver_StockpileWaterBottles` 重写 `MakeNewToils`（3个lambda：goto→fill→produce），产出 `DBH_WaterBottle`（defName 字符串，非硬编码类型）。
- 重构方案（不再自己碰内部字段）：`RedirectFill` 用 `[ThreadStatic] _inFill` 防递归，调用 DBH 原版 `MakeNewToils` 拿原版 toils（DBH 自己扣管网水/按正确单位产 DBH_WaterBottle），再 `Concat` 一个 `BuildMEESwapBottleToil`：扫设施周围6格 `DBH_WaterBottle`→销毁并统计 stackCount→在设施旁空地 Spawn 等量 `MEE_WaterBottle`。扣水/单位/配额全归 DBH，MEE 只换皮。
- 清理：删除 `BuildMEEFillToils` 与无用缓存字段（`_capTypeCache/_capTypeQueried/_waterStorageFieldCache/BottlesPerBatch/WaterPerBottle`）。`JobDriver.Map` 是 protected → 改用 `driver.pawn.Map`。
- 模块 `dotnet build -c Release` 0错0警；DLL md5 `300f5a88…` 已部署。
- 教训：MEE 接管 DBH 取水时不要自己读内部字段算单位/配额，应委托 DBH 原版 Job 执行后再换瓶（同 FDE 模式）。
